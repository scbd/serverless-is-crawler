CloudFront · Lambda@Edge

How a request becomes a prerendered page

Every site sits behind one CloudFront distribution with two Lambda@Edge functions on the default behavior: serverless-is-crawler-Http on viewer request, and serverless-is-crawler-Redirect on origin request. Together they decide, per request, whether CloudFront fetches the page from the real origin or from the prerender service.

Both functions live in this repo: redirect-crawler/app.js (origin request) and http-header/app.js (viewer request).

What each hop actually checks

The full decision logic behind the two boxes above.

viewer request

serverless-is-crawler-Http

http-header/app.js

  • Runs es6-crawler-detect plus a small custom list (e.g. uptimerobot) against the User-Agent.
  • Flags AI agents (gptbot, claude, perplexity, …) by trusting an upstream WAF header x-is-ai-agent first, falling back to a UA substring match.
  • If either check hits, sets X-Is-Crawler: true and forwards the original UA as X-Origin-User-Agent so it survives the origin rewrite.
  • Short-circuits entirely if x-is-prerender is already set — a request that's already been prerendered isn't re-flagged.
origin request

serverless-is-crawler-Redirect

redirect-crawler/app.js

  • Blocks known bad-spider UAs (403) and duplicate or malformed countries/kb paths (404) before anything else runs.
  • Requires X-Is-Crawler: true and prerender still eligible to act.
  • Eligibility drops to false for non-HTML asset extensions, when x-is-prerender or x-prerender says so, or — on www.cbd.int — outside the allow-listed SPA sections.
  • When still eligible, rewrites the origin to the prerender service with path /api/render-html?_escaped_fragment_=true&url=….

Inside the prerender service

The prerender service is a small Express app (url-to-html-api) wrapped around one shared headless Chrome instance, not a request-per-invocation function.

This is also the source of the process inflight running N / no request in flight log lines — processInflightRequest() in src/renderer.js logs on every 200ms/2s poll tick, whether or not there's work to do.

Header contract between the two functions

What gets read and written at each hop.

HeaderSet byRead byPurpose
X-Is-Crawler viewer request origin request Marks the request as crawler/bot traffic; gates the prerender rewrite.
X-Origin-User-Agent viewer request — (passed through) Preserves the real UA once the origin becomes the prerender service.
X-Is-AI-Agent viewer request — (passed through) Distinguishes AI/LLM crawlers from traditional search-engine bots.
x-is-prerender upstream / prior hop both functions When true, tells both hops this request was already prerendered — skip re-flagging and re-rewriting.
x-prerender upstream / prior hop origin request Secondary opt-out: value 1 forces prerender = false.
Behaviors and origin groups (US-WWW / GEO-WWW) per the CloudFront console configuration.
